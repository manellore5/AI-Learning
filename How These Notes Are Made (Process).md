# How These Notes Are Made — Process

How a Cohort 004 lesson goes from a video on aihero.dev to a section in `Cohort 004 - New Video Notes.md` and, finally, the team announcement. This is the **manual** workflow we actually used (not the repo's automated `/learn` skill — see the note at the end on why).

---

## Why this is a manual process
- The videos live on **aihero.dev**, a **paid course player**. It is **not** a YouTube/yt-dlp-supported site, so the `/learn` skill's automatic transcript fetch returns *"Unsupported URL"*.
- So instead of auto-fetching, **the source text is pasted in by hand** and the notes are composed from it.

## What gets pasted in (the source)
For each lesson, two things from the aihero lesson page:
1. **The lesson article / readme** — the written write-up (headings, bullet points, code blocks, screenshots).
2. **The video transcript** — the spoken walkthrough, usually with `mm:ss` timestamps.

Having both matters: the article gives clean structure and exact commands/links; the transcript adds nuance, asides, and the "why" in Matt's own words. The notes are reconciled from both.

## The 5-step loop (per video)
1. **Paste** the lesson's article + transcript into the chat.
2. **Confirm placement** — which course section it belongs to (Before We Start, Day 1, … Day 6) and whether it's a main lesson or an **appendix**.
3. **Compose the section** in a consistent shape (below), distilling — not transcribing. Aim for *adequate detail*: enough to understand the lesson without watching it, but not a full rewrite.
4. **Append** the new section to the bottom of `Cohort 004 - New Video Notes.md`.
5. **Update the index** at the top — move the item from *Still to do* into *Covered so far* (appendices go under their own sub-group).

## The per-section template
Each video section in the running file follows the same structure so the doc stays scannable:

```
## <N>. <Video Title>
**Section:** <course section> · **Source:** <source path> · <optional: skill/extra>

### Key points            (or a problem→solution split, or numbered phases — fit the content)
- <distilled bullet>
- <bold key terms>, `inline code` for commands/files/skills

> Optional takeaway / rule-of-thumb callout.
```

Conventions used throughout:
- **Bold** for key terms and the important nouns; `code font` for commands, filenames, tool/skill names.
- A leading **one-line italic description** under each video title in the announcement version (the "what it covers" blurb).
- Distill to bullets; only use numbered lists for genuinely sequential things (e.g. the 7-phase Final Workflow).

## The running file: `Cohort 004 - New Video Notes.md`
- **One file for the whole series** (decided deliberately — a bounded ~7-video changelog reads better as a single skimmable doc than scattered files, and it's easy to share).
- Top of file has a live **index**: *Covered so far* (numbered) + an *Appendices* sub-list + *Still to do*.
- Local working doc — **not committed** to the AI-Learning git repo. (Two of the appendices — Greenfield Projects, Grill with Docs — *also* have fuller standalone notes in the repo via `/learn`; that overlap is intentional, since the repo is the durable knowledge base and this file is the transient "what's new this cohort" digest.)

## From notes → team announcement
1. The running notes are condensed into a **team announcement**: a title, an intro line, then section-by-section entries (▶ video title → italic one-liner → key-point bullets).
2. Delivered in two forms:
   - **Teams/chat message** — markdown formatted (`##` headers, `-` bullets, `**bold**`), pasted directly into Teams.
   - **Word document** — `Cohort 004 - Team Announcement.docx`, generated by `build_announcement_docx.py` (uses the `python-docx` library) with styled headings, blue video titles, inline-code styling, bullets, and numbered steps. Re-runnable for edits.
3. The full `.md` notes file is attached to the announcement for anyone who wants the deep dive.

## Tooling summary
| Purpose | Tool |
|---|---|
| Capture/edit the notes | Plain markdown (`.md`) |
| Generate the Word doc | Python + `python-docx` (`build_announcement_docx.py`) |
| (Repo notes, when used) | The `/learn` skill → per-video `.md` + auto-index + git commit |

## Note on the `/learn` skill
The repo has an automated `/learn` pipeline (transcript → notes → index → commit → push). It works for **YouTube / yt-dlp-supported** URLs. Because aihero.dev is paywalled, it falls back to the manual paste flow described here. If a lesson is ever worth keeping permanently, it can be ported into the repo as a proper `/learn` note.
